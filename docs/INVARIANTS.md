# Invariants

The testable invariants of SenstoSales. Each row has an ID, a precise statement, where it comes from (the legacy
business spec section as "spec §n" and/or the owner decision `A-n`, plus the `ARCHITECTURE.md` section), the planned
enforcement point and test type, and a status.

Rules:

- Rows are never removed or renumbered. A spec that adds an invariant appends its row here in the same PR.
- Every row comes from the business spec or an owner decision (`ARCHITECTURE.md` Appendix A). Nothing here extends
  `ARCHITECTURE.md`, and nothing deferred to `EDGE_CASES.md` appears here.
- Quantities are written in units for readability; the code holds them as integer milli-units, money as integer
  1e-5 units (INV-01). "tol" is 0.001 (INV-02).
- **Status** is `specified` until the named check or test exists; it then becomes `active (<test or check>)`. An
  invariant is binding from the moment it is specified: review applies it until the check exists.

Test types: **domain** (Vitest unit test in `packages/domain`, table-driven, literal values), **parser** (golden
test on anonymised fixtures), **API** (Hono `app.request()` against in-memory SQLite), **export** (golden file),
**e2e** (Playwright), **CI** (a CI job or lint rule), **review** (reviewer checklist).
